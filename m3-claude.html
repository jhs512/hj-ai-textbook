모듈 3 · 1.5H · Claude

Claude 업무 활용

긴 규정·공고문을 통째로 넣어 필요한 조항만 뽑고, 표를 대시보드로 바꾸고, 문서의 톤을 공문체로 다듬습니다. 규정·매뉴얼을 묶은 Projects로 '근거 있는 답변'을 받는 법을 익힙니다.

학습 목표
  • 긴 문서(규정·공고·보고서)를 넣고 조항 번호·페이지가 붙은 요약을 받는다.
  • 표·양식을 Artifact로 만들어 바로 쓸 수 있는 대시보드·체크리스트로 바꾼다.
  • 같은 내용을 공문체·안내문체·보도자료체로 바꿔 쓴다.
  • Claude Projects에 규정·매뉴얼을 묶고 "근거 조항을 인용해 답하라"는 지침을 건다.
  • 나라장터 입찰공고·계약규정 PDF에서 우리 건에 적용되는 조항을 찾아 요약한다.

강사 노트 · Claude의 성격
  • 긴 문맥: 수백 쪽 분량도 한 번에 읽습니다. "요약해 줘"보다 "n조 n항처럼 조항 번호를 붙여 인용해 줘"가 Claude의 강점을 살립니다.
  • Artifact: 코드·문서·표·HTML 결과물을 오른쪽 별도 창에 띄워 줍니다. ChatGPT 캔버스와 비슷하지만, HTML 대시보드처럼 작동하는 결과물을 만들 수 있다는 점이 다릅니다.
  • 무료 한도: 긴 PDF를 여러 개 올리면 한도가 금방 옵니다. 실습 PDF는 30쪽 이내로 준비하고, 한도가 오면 짝 실습으로 전환합니다.

3.1 긴 문서·규정 요약

규정 요약에서 가장 위험한 것은 "그럴듯한데 조항이 틀린" 답입니다. 그래서 항상 조항 번호·페이지를 함께 요구하고, 답변 형식을 "조항 → 원문 인용 → 해석" 3단으로 고정합니다.

실습 3-1. 규정 PDF에서 적용 조항 찾기

  1. 실습 규정 준비우리 기관 홈페이지에 공개된 규정(예: 계약사무 규정, 여비 규정, 복무 규정) PDF 1개. 없으면 국가법령정보센터(law.go.kr)에서 「국가를 당사자로 하는 계약에 관한 법률 시행령」을 PDF로 저장.
  2. 새 대화 → 첨부 → 아래 프롬프트노란 부분을 내가 실제로 궁금한 상황으로 바꿉니다.
  3. 인용된 조항을 원문에서 확인Ctrl+F로 조항 번호를 찾아 인용문이 실제와 같은지 봅니다. Claude는 인용을 비교적 정확히 하지만 해석 부분은 AI 의견임을 명심.
첨부한 규정에서 다음 상황에 적용되는 조항을 모두 찾아 주세요. 상황: 예산 3,000만 원 규모의 연구용역을 수의계약으로 체결하려고 함. 계약 상대방은 작년에도 유사 용역을 수행한 업체. 답변 형식(조항마다 반복): 【조항】 제○조(제목) 제○항 【원문】 "해당 조항 원문을 그대로 인용" 【적용】 이 상황에 어떻게 적용되는지 2줄 이내 【주의】 예외·단서 조항이 있으면 표시 마지막에: - 적용 가능 여부에 대한 종합 판단 (단, "최종 판단은 계약 담당 부서 확인 필요"를 명시) - 규정에 명시되지 않아 추가 확인이 필요한 사항 목록

실습 3-2. 긴 보고서 → 결재권자용 1쪽 요약

첨부한 보고서(○○ 사업 중간 평가 보고서, 약 60쪽)를 결재권자가 3분 안에 읽을 1쪽 요약으로 만들어 주세요. 구성: 1. 한 줄 결론 2. 핵심 수치 5개 (표: 항목 | 수치 | 원문 페이지) 3. 잘된 점 3가지 / 문제점 3가지 (각 1줄, 원문 페이지 표기) 4. 결재권자가 결정해야 할 사항 (있으면) 5. 보고서가 다루지 않은 것 (요약자가 꼭 알아야 할 공백) 규칙: 모든 항목에 원문 페이지를 괄호로 표기. 보고서에 없는 평가·추측은 쓰지 말 것.
체크포인트
  • 인용된 조항 번호와 원문이 실제 규정과 일치하는가? (최소 2개 확인)
  • "[추가 확인 필요]" 목록이 실제로 규정에 없는 내용인가?
  • 요약에 붙은 페이지 번호가 맞는가?

3.2 표·양식 간 대시보드 Artifact 생성

Artifact는 Claude가 만든 결과물을 오른쪽 창에 띄우는 기능입니다. 글·표뿐 아니라 작동하는 HTML 화면을 만들 수 있어, 엑셀 표를 "보기 좋은 현황판"으로 바꾸거나 체크리스트 양식을 바로 쓸 수 있게 만듭니다.

실습 3-3. 실적 표 → 인터랙티브 대시보드

  1. 가상 데이터 준비아래 프롬프트의 표를 그대로 쓰거나, 2.5에서 만든 ALIO 비교표를 붙여 넣습니다.
  2. HTML 대시보드 요청"Artifact로", "HTML 한 파일로"를 명시합니다.
  3. 오른쪽 창에서 조작필터·정렬이 작동하는지 확인. 마음에 안 드는 부분은 "막대 색을 기관별로 다르게", "합계 행 추가"처럼 이어서 요청.
  4. 다운로드·공유Artifact 오른쪽 위 메뉴 → "다운로드"(HTML 파일) 또는 "게시"(링크 공유, 공개 자료만). 받은 HTML은 브라우저에서 바로 열립니다.
아래 표를 HTML 한 파일짜리 대시보드 Artifact로 만들어 주세요. 요구사항: - 상단에 요약 카드 4개: 총 접수, 총 처리, 평균 처리일수, 처리율 - 가운데: 유형별 접수/처리 막대 그래프 (외부 라이브러리 없이 CSS 또는 SVG로) - 하단: 원본 표, 열 머리글 클릭 시 정렬, 유형 필터 드롭다운 - 글꼴은 시스템 기본 한글 글꼴, 인쇄(A4) 시 한 장에 들어가게 - 데이터는 파일 안에 배열로 두어 나중에 내가 숫자만 바꿀 수 있게 주석 표시 --- 데이터 --- 유형 | 접수 | 처리 | 평균처리일수 증명발급 | 1,240 | 1,238 | 1.2 시설이용 | 860 | 842 | 3.4 정보공개 | 215 | 198 | 8.9 불편신고 | 330 | 301 | 6.1 기타 | 145 | 140 | 2.8

실습 3-4. 체크리스트 양식 Artifact

계약 체결 전 서류 점검표를 HTML Artifact로 만들어 주세요. - 항목: 사업자등록증, 국세·지방세 완납증명, 청렴계약 이행서약서, 보증보험증권, 기술능력 평가서 - 각 항목: 체크박스 | 항목명 | 확인일 | 확인자 | 비고(입력칸) - 하단에 "전체 체크 완료 시 '점검 완료' 표시" - 인쇄 버튼, A4 세로 1장
강사 노트

Artifact는 "화려한 결과"로 흐르기 쉽습니다. 업무용 포인트는 두 가지입니다. ① 데이터와 화면을 분리해 달라고 요구하면 다음 달에 숫자만 바꿔 재사용할 수 있다. ② "게시" 기능은 외부 공개이므로 내부 수치는 절대 게시하지 않는다.

3.4 AI 에이전트: Claude Projects로 근거 있는 답변 받기

Projects는 지침 + 참고 문서 + 관련 대화를 한 폴더에 묶는 기능입니다. 규정·매뉴얼을 넣어 두면 매번 첨부하지 않아도 되고, "이 문서들 안에서만, 조항을 인용해 답하라"는 지침을 걸 수 있습니다.

실습 3-6. '규정·매뉴얼 Project' 만들기

  1. 프로젝트 생성왼쪽 사이드바 "프로젝트" → "새 프로젝트". 이름: ○○ 규정·매뉴얼, 설명: "계약·여비·복무 규정 질의응답용".
  2. 프로젝트 지식 추가오른쪽 "프로젝트 지식" → 파일 업로드. 3.1에서 쓴 규정 PDF + 업무 매뉴얼(공개본) 2~3개. 텍스트로 직접 추가도 가능(예: 기관 용어집).
  3. 지침 설정"지침 설정" → 아래 템플릿 붙여 넣기.
  4. 질문 테스트프로젝트 안에서 새 대화: "출장 중 숙박비 상한은?" 같은 질문. 답변에 조항 번호와 인용이 붙는지, 문서에 없는 질문엔 "문서에 없음"이라 하는지 확인.
  5. 대화 누적프로젝트 안의 대화는 자동으로 모입니다. 자주 묻는 질문의 답을 "프로젝트 지식"에 텍스트로 추가해 두면 다음 답변이 더 정확해집니다.
## 역할 당신은 ○○공단의 규정 담당자입니다. 프로젝트 지식에 있는 규정·매뉴얼만을 근거로 답합니다. ## 답변 규칙 1. 모든 답변은 반드시 근거 조항을 인용합니다. 형식: 「규정명」 제○조 제○항 — "원문 인용" 2. 프로젝트 지식에 근거가 없으면 "첨부된 규정에서 근거를 찾지 못했습니다. 확인이 필요합니다."라고 답하고 추측하지 않습니다. 3. 상위 법령이나 외부 지침을 언급해야 할 때는 "일반적으로 ~로 알려져 있으나, 프로젝트 문서 밖의 정보입니다"라고 구분합니다. 4. 해석이 갈릴 수 있으면 가능한 해석을 모두 제시하고 "담당 부서 확인 필요"를 붙입니다. ## 출력 구조 【결론】 한 줄 【근거】 조항 인용 (여러 개 가능) 【적용】 질문 상황에 맞춘 설명 【확인 필요】 규정에 없거나 모호한 점 ## 어투 간결한 경어체. 단정 대신 "~로 보입니다", "~에 해당합니다".
보안 주의 · 프로젝트 지식

프로젝트에 올린 문서는 그 프로젝트의 모든 대화에 계속 사용됩니다. 공개된 규정·매뉴얼만 넣습니다. 내부 지침 중 비공개 문서, 감사 결과, 개인정보가 포함된 사례집은 넣지 않습니다. 팀 공유(Team 플랜)는 기관 지침 확인 후.

강사 노트 · 모듈 2 GPT와 비교

"GPT는 '보고서 쓰는 사람'을 만든 것이고, Project는 '규정 서랍'을 만든 것입니다. 구조는 같습니다(지침 + 파일). 다만 Claude Projects는 긴 문서를 여러 개 넣어도 잘 읽고, 대화가 프로젝트 안에 모여 '이 건의 히스토리'가 된다는 점이 다릅니다."

3.5 [공공 예제] 나라장터 입찰공고·계약규정에서 적용 조항 찾기·요약

공공 예제 · 나라장터 (국가종합전자조달, g2b.go.kr)

나라장터 입찰공고에는 공고문·과업지시서·제안요청서·계약조건이 PDF/HWP로 첨부됩니다. 입찰 참여 기관이든 발주 기관이든 "우리에게 적용되는 조건과 마감·제출 요건"을 빠르게 뽑는 일이 반복됩니다.

자료 준비

  1. g2b.go.kr → 입찰공고 검색공고명에 "용역" 또는 "정보시스템"으로 검색, 공고문·제안요청서가 PDF로 첨부된 건 1개 선택. HWP만 있으면 한글에서 PDF로 저장.
  2. 계약규정 준비3.1에서 쓴 기관 계약 규정 PDF 또는 「국가를 당사자로 하는 계약에 관한 법률 시행령」·「(계약예규) 용역계약 일반조건」(조달청 홈페이지 공개).
  3. 3.4에서 만든 프로젝트에 두 문서를 모두 추가이제 프로젝트 안에서 질문합니다.

실습 3-7. 공고문 핵심 요건 추출

프로젝트 지식의 「○○ 시스템 구축 용역」 입찰공고문과 제안요청서에서 다음을 추출해 표로 정리해 주세요. 각 항목에 출처(문서명·페이지)를 적어 주세요. 1. 일정: 공고일, 입찰등록 마감, 제안서 제출 마감, 개찰, 제안발표(있으면) 2. 참가 자격: 업종·면허, 실적 요건, 지역 제한, 공동수급 허용 여부 3. 제출 서류 목록 (필수/선택 구분) 4. 평가 방식: 기술/가격 배점, 적격심사 또는 협상에 의한 계약 여부 5. 계약 조건 중 특이사항: 하자보수 기간, 지체상금률, 선금 지급 조건, 보안 요구사항 표 아래에 "주의: 놓치기 쉬운 조건" 3가지를 공고문 원문 인용과 함께 적어 주세요.

실습 3-8. 공고 조건 ↔ 계약규정 대조

위에서 뽑은 계약 조건(지체상금률, 선금, 하자보수 기간)이 프로젝트 지식의 계약 규정 / 용역계약 일반조건과 어떻게 대응되는지 대조표를 만들어 주세요. 열: 항목 | 공고문 조건 (출처) | 규정 조항 (「규정명」 제○조, 원문 인용) | 일치 여부 | 비고 - 규정에 상한·하한이 있는 항목은 공고 조건이 그 범위 안인지 표시 - 규정에서 찾지 못한 항목은 "규정 미확인"으로 두고 추측하지 말 것 - 마지막에 "담당자가 확인해야 할 사항" 목록

실습 3-9. 결과를 보고용 요약으로

위 두 표를 바탕으로 "입찰 참여(또는 공고 검토) 의견" 1쪽 요약을 작성해 주세요. 형식: 1. 공고 개요(3줄) / 2. 핵심 일정 / 3. 자격·제출 요건 충족 여부 점검표 / 4. 리스크 및 확인 필요 사항 / 5. 의견 개조식, 각 항목 출처 페이지 표기. 결정 표현은 "~검토 필요"로.
